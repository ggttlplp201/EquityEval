# Web workspace

The X1 Sector Explorer provides a graph-first development interface using a
checked, explicitly fictional snapshot. `/sectors` reports production data
prerequisites; `/development/sectors` opens the demonstration. The Company, News and Help development routes extend the same visual system.
These bounded views do not implement the S6 API or finish production S8/F1.

From the repository root:

```sh
npm run dev --workspace @equity/web
npm run build --workspace @equity/web
npm run start --workspace @equity/web
```

The interface supports sector and industry bars, dated history, company
histograms, growth-versus-P/E scatter, same-method market references, coverage,
source drawers and the exact frozen company snapshots used in each result.
Missing and nonmeaningful rows remain visible. Below-gate values are outlined;
they are not ranked or placed in the scatter. Breadth is an equal-company
measure, with method switching disabled. Its scatter explicitly uses sector
totals for both axes.

The fictional fixture is generated by the shared Python fundamentals and sector
calculations. No financial ratios, coverage gates, histogram membership or
percentiles are calculated in the browser. The presentation exporter only
formats values and constructs chart geometry; it rejects orphan source details.
Regenerate the complete artifact from the repository root:

```sh
.venv/bin/python scripts/project_python.py scripts/build_sector_fixture.py
.venv/bin/python scripts/project_python.py scripts/export_sector_explorer.py \
  var/sector-explorer-raw.json apps/web/src/features/sectors/fixture.json.gz
```

The gzip artifact is deterministic and keeps complete provenance. The server
expands it for the development page. All date, metric and method variants are
loaded together, so the uncompressed development payload is large; a reviewed
production API will request individual immutable snapshots instead. The internal
TypeScript view model is not a proposed public API contract.

Validation uses `npm run typecheck --workspace @equity/web`, the root lint and
Python presentation tests, `next build`, and browser checks of desktop/mobile,
linked controls, source drilldown, missing states and hydration. The release
milestone records what was actually verified.

## Supplied redesign — D1a

The 2026-09-19 dark redesign is applied to the existing Sector Explorer.
Its original HTML/README are preserved under `docs/originals/ui-redesign-2026-09-19`;
`docs/design/ui-redesign/reconciliation.md` compares every one of the 143 design
requirements. The prototype's arithmetic and invented Company/News records are
not imported. Financial math, fixture values, types and eligibility remain in
the existing pipeline. D1b adds Company/News/Help routes; R1 persistence and live services remain
planned. The production-readiness route retains its gates.

One mint hue uses matching dash patterns for up to four history series, rather
than dim opacity-only lines. Narrow chart regions and tables scroll inside their
panels; their data/source alternatives remain available. See D1a's milestone for
actual checks and remaining acceptance.

## Connected development views — D1b

- `/development/company?company=computing-01&asOf=2026-06-30`: guided existing
  metrics and amounts, exact evidence, 3/5/10-year history gaps and dated value
  comparison. The page sends only one issuer's available-by-date results to the
  client. Unknown issuer/date values return not found. Sector links preserve the
  selected constituent and snapshot date.
- `/development/news`: proposed macro/stock-topic coverage and unconfigured
  collection, assessment, host and in-app/desktop/email delivery. No news source,
  background worker, alert subscription or notification is activated.
- `/help`: development instructions, contextual/searchable glossary and browser
  print support. Complete U1 release workflows remain pending.

The Company fixture reuses the same raw core results and source details:

```sh
.venv/bin/python scripts/project_python.py -m scripts.export_company_fundamentals \
  var/sector-explorer-raw.json apps/web/src/features/company/fixture.json.gz
```

Only two company snapshot dates are supplied. Longer selected windows expose
missing quarters and never borrow the separate Sector histories. All source
amounts are USD without a million/billion multiplier. New presentation tests
compare every supplied metric against the unchanged Sector fixture. Read
`docs/milestones/D1b-company-news-help.md` for validation and remaining work.

## Real-source pilot — D2

`/development/pilot?company=CRCL` uses a separate real-source artifact. It keeps
all seven requested companies in a dated identity/business/coverage roster.
CRCL FY2025 has two exact observed amounts cross-checked between archived SEC
Company Facts and the original filing. All derived metrics and company-history
series remain unavailable while actual publication/PIT and completeness
prerequisites are unresolved. Research-reference dates and observed-filing dates
are distinct.

Reproduce without provider or database access:

```sh
.venv/bin/python scripts/project_python.py -m scripts.export_real_pilot
.venv/bin/python scripts/project_python.py -m scripts.export_real_pilot --check
```

Read `docs/milestones/D2-real-data-pilot.md` for checks and concrete next steps.
The pilot does not convert the seven stocks into a sector universe, start
monitoring, or replace the separate fictional Company/Sector fixtures.

## Synthetic reverse DCF — S8a

`/development/valuation` renders existing generated S7a public payload contracts.
Python validates separate fictional presentation manifests and calculates all
results with the unchanged core. The page sends only the selected example to
the browser; selecting another example uses a local GET navigation.

```sh
.venv/bin/python scripts/project_python.py scripts/export_valuation.py --check
node --test tests/web/valuation.test.cjs
# Against a running production preview, using an installed Playwright module:
EQUITY_PREVIEW_URL=http://127.0.0.1:3102 \
  node --test tests/web/valuation-browser.cjs
```

Set `EQUITY_PLAYWRIGHT_MODULE` to an existing Playwright module directory if it
is not on Node's resolution path. Browser tests launch headless Chromium and
only access localhost. No database, provider or mutation endpoint is used.
See `docs/milestones/S8a-synthetic-valuation-ui.md` for scope and verification.

S8a displays numbers with at most four decimal places and no trailing zeros.
Decimal strings round halfway away from zero without a binary-float conversion;
percentages shift before rounding. Structured solver/assumption displays format
only known numeric fields. All source strings remain unchanged in the drawer.


## Fictional S6a fundamentals — S8b

`/development/company/ratios` presents a selected validated FundamentalsPayload,
separate from D1b Company/Sector identity. Generate with
`.venv/bin/python scripts/project_python.py -m scripts.export_fundamentals`;
append `--check` for deterministic verification (included in `make lint`).
Inputs live under `scripts/fixtures/fundamentals-presentation.json` and the typed
production helper; neither imports test fixtures. The page sends only the exact
selected offline snapshot. S6a public types and financial formulas are unchanged.

`node --test tests/web/fundamentals.test.cjs` checks presentation. The browser
suite is `tests/web/fundamentals-browser.cjs`, with the same local preview and
Playwright environment options as S8a. See `docs/design/s8b/acceptance.md`, the
S8b milestone and `docs/user-manual/saved-fundamentals.md` for limits and usage.


## Saved financial statement lines — S8c

`/development/company/financials` uses a separate local synthetic presentation
payload. Generate via `.venv/bin/python scripts/project_python.py -m
scripts.export_financials` (on one line); `--check` is part of lint. Source recipe:
`scripts/fixtures/financials-presentation.json`. No shared schema/API change.
Three editions: original annual, revised annual and directly reported quarter.
Balance-sheet rows retain instant periods; TTM is unsupported and disabled.
Run `tests/test_financials_presentation.py`, `node --test
tests/web/financials.test.cjs`, and `tests/web/financials-browser.cjs` using the
same existing Playwright module and local preview options as S8a/S8b.
See `docs/user-manual/saved-financials.md` and `docs/design/s8c/acceptance.md`.
